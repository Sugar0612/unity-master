### A1（1.5/3）yield return 那一刻
"方法返回、state 变化" ✓，但只讲了**你这一半**，丢了大头：返回时 **MoveNext 返回 true、Current 被设成 yield 出去的对象**——引擎拿到 Current 才知道"下次什么时候叫醒你"（null=下一帧，WaitForSeconds=攒时间）。完整句式："方法返回 true + 交出 Current，引擎记账，条件满足再调 MoveNext 从 state 跳入点继续"。**协程是两个人的事：状态机（编译器）+ 调度器（引擎）**——你只答了前一个的半场。

### A2（1.5/3）——有一处因果错误 + 一处我的讲义缺口

## B（待做）——"没思路"按方法 v2 处理：骨架在这，你填肉

知识缺口是我的支持问题。**黑板示范一层（泵 + null 情况），你实现其余**（Wait、嵌套、Stop、演示、预测）：

```csharp
public class CoroutineDriver : MonoBehaviour
{
    public static CoroutineDriver Instance { get; private set; }
    private readonly List<Runner> _runners = new();

    void Awake() { Instance = this; }

    public Handle Start(IEnumerator routine)
    {
        var r = new Runner(routine);
        _runners.Add(r);
        return new Handle(r);
    }

    void Update()                       // 这就是你的"引擎"
    {
        for (int i = _runners.Count - 1; i >= 0; i--)   // 倒序遍历——W2 防重入思想
        {
            _runners[i].Tick(Time.deltaTime);
            if (_runners[i].Done) _runners.RemoveAt(i);
        }
    }
}
```

你要写的 `Runner`（核心作业）：`Tick` 里调 `routine.MoveNext()`，然后**看 Current 的类型分派**：
- `null` → 本帧结束，下帧再 Tick
- `Wait`（你自己定义的等待类，含秒数字段）→ 你自己累计 deltaTime，够了才算完
- `Handle`（嵌套）→ 查子 Runner 的 Done，子完父才继续
- MoveNext 返回 false → Done = true

再加：`Stop(Handle)`（标记 Alive=false 并从列表移除，注意父停子也要死）、`StopAll()`、演示场景、**预测题**（1000 帧的 GC 分配：状态机 new 是编译器强制的，你自己的 Tick 路径上有什么分配？Current 装箱了吗？——想想 yield return null 时 Current 是 object 槽位装着 null 引用，装箱吗？）

## C1（1/3）——尝试了，但设计没到位，且有一个复发 bug

### 复发 bug（这次最重的扣分点）：`isGoOn & IsGoOn`

**位运算 & 又出现了**。代码摸底报告里就记录过你 RSHE 的 `isFinish = isFinish & (...)`——同一个习惯第二次进档案（错题 #17）。这次碰巧没炸（两边都是 bool、无短路需求），但它是不分场景的手滑，逻辑判断永远写 `&&`。

### 设计层：你给的是"快照否决权"，不是"生命周期"

参数 `bool isGoOn` 是 **Delay 调用那一刻的值拷贝**——之后翻转变量，协程里的判断不会跟着变（还记得 W1 的副本语义吗：装箱进盒子的是**当时的拷贝**，栈上的原值怎么改都不影响盒子）。所以你的方案做不到"事后取消某个计时器"——而那正是 GameHelpler 用 `WaitUntil(IsGoOn==false)` 硬凑的功能。

任务要求的是**句柄/token**：调用方拿着一个活的东西，随时能取消这一个计时器，不影响别人。参考架构（和 B 的 Handle 是同一个模式，W3 一鱼两吃）：

```csharp
public readonly struct TimerHandle { internal readonly int Id; /* ... */ }

public static TimerHandle Delay(float delay, Action callback)  // 返回句柄
public static void Cancel(TimerHandle handle)                  // 取消这一个
public static void PauseAll() / ResumeAll()                    // 你的"总控开关"放这层
```

**你的产品判断是对的**（"项目需要总控开关"）——正确架构是**两层**：全局 Pause/Resume（业务层）+ 每计时器句柄 Cancel（控制层）。你现在的方案把两层混在一个 bool 里，两层都做不全。为什么全局开关单独作为唯一机制是错的——W2 的 scope 思想：**清理/控制必须认归属**，全局开关不认识"哪个计时器该停"。
