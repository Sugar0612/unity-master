## B 的三个 bug

### Bug 1（最重）：StopAll 跳号 → 僵尸句柄 + 父协程永久卡死

```csharp
public void StopAll()
{
    for (int i = 0; i < _handles.Count; ++i)   // 正向遍历
        Complete(_handles[i]);                  // Complete 里 _handles.Remove → 列表左移！
    _handles.Clear();
}
```

`Complete` 会把元素从列表**移除**，正向遍历 + 移除 = 跳号：i=0 完成 h0（列表变 [h1,h2]）→ i=1 拿到的是 **h2**——**h1 被跳过**。被跳过的 h1：标志位永远停在 isRunning=true，但被 Clear 出了列表——**僵尸句柄**。连锁反应：任何 `watingHandle == h1` 的父协程，`if (watingHandle.isRunning) return;` **永远为真，父协程永久卡死**。
修法一行：**快照遍历** `foreach (var h in _handles.ToArray()) Complete(h);`（或倒序+删完不 Clear 的写法）。
**错题 #19**——这和 W2 讲的"发布路径重入"是同族：**遍历中修改集合**。你的 Update 用倒序躲开了，StopAll 忘了同一个原则要全场适用。

### Bug 2：父 Stop，子不死（任务卡明确要求 #5）

`Stop(parent)` → `Complete(parent)`——但 parent 正等着的 `watingHandle`（子协程）还在列表里继续跑。孤儿孩子会一直跑到自己结束。修法：`Complete` 里级联一行 `if (watingHandle != null) Complete(watingHandle);`（自引用你已在 ProcessYield 挡了，无死循环风险；跨引用环的极端场景想一下要不要防，答卷里写一句）。

### Bug 3：泵的中途重入可炸可双跑

协程体内完全可以调 `driver.Stop(...)`/`StopAll()`（演示场景里你就会写这种）——列表当场缩短，外层 `for` 的 `i` 失配：轻则 `_handles[i]` **越界异常**，重则索引错位导致**某个协程一帧被 Tick 两次**。修法：循环体开头加 `if (i >= _handles.Count) continue;`（防御）或干脆 Update 也用快照遍历（彻底，每帧一次数组分配——用你的 GC 预测题判断值不值）。

### 三个小注记（不阻塞）

- `waitingNextFrame` 标志是**装饰品**：置位后下一帧先清掉再直接 MoveNext——真正挡住"当帧继续"的只是"Update 每帧只跑一次"这个事实。删掉它逻辑不变（想清楚为什么）。
- 非法 sub handle 被静默忽略（行为退化成 yield null）——你对外来类型会抛异常，对非法句柄却沉默，标准不统一。
- **和原生 StartCoroutine 的时序差异**（对照实验素材，直接给你）：① Unity 的 StartCoroutine **同步执行到第一个 yield**（调用当帧就跑首段）；你的 Start 要等下一帧 Update 才第一次 MoveNext ② Unity 的 yield null 在 **Update 之后**恢复，你在 Update 内恢复。

## C2：第三次拖延 → 骨架干预（方法 v2）

你要写的东西 **和 B 的 Handle 是同一个模式换个马甲**——句柄=查注册表的活钥匙。骨架：

```csharp
public readonly struct TimerHandle { internal readonly int Id; internal TimerHandle(int id) => Id = id; }

private static int _nextId;
private static readonly HashSet<int> _active = new();   // 注册表：还活着的计时器 id

public static TimerHandle Delay(float delay, Action callback)
{
    int id = ++_nextId;
    _active.Add(id);                                     // 登记
    _component.StartCoroutine(DelayRoutine(id, delay, callback));
    return new TimerHandle(id);
}

public static void Cancel(TimerHandle h) => _active.Remove(h.Id);  // 摘牌=取消

public static void PauseAll()  { /* 总控层：你的业务开关放这，语义是暂停不是取消 */ }
public static void ResumeAll() { /* ... */ }

private static IEnumerator DelayRoutine(int id, float delay, Action callback)
{
    yield return new WaitForSeconds(delay);
    if (_active.Remove(id))                 // 到点时检查：牌还在才执行（被 Cancel 就跳过）
        callback?.Invoke();
}
```

你要做的：填 Pause/Resume 两层怎么和 id 机制共存、真文件落地（`git diff`）、用自己的话写"快照参数 vs 活句柄"（#18 消灭条件）——提示就一句：**W1 副本语义**（bool 拷贝进协程是死快照）对 **W2 scope**（注册表里查得到的活引用）。
