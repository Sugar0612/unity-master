## B3-R ✗ 未通过——修复无效，且问到了关键处

### 你的 OnDisable 修复是无效操作

```csharp
onClickEnter -= () => RaiseTrigger(InteractionTrigger.Selected);   // ← 这行什么都删不掉
```

**为什么无效——这次用编译器的视角完整讲一遍**：

同一个 lambda 代码，写在两个地方 = 编译器生成**两个不同的方法**：

```csharp
// OnEnable 里的那句 lambda（位点 A）编译后：
var d1 = new Action(<M>b__12_0);        // 生成方法 12_0
onClickEnter = Delegate.Combine(onClickEnter, d1);

// OnDisable 里的那句 lambda（位点 B）编译后：
var d2 = new Action(<M>b__12_1);        // 生成方法 12_1 —— 和 12_0 是两个方法！
onClickEnter = Delegate.Remove(onClickEnter, d2);
```

`Remove` 按 **(Target, Method) 相等性**在链上找要删的委托：d1 的方法是 `12_0`，d2 的方法是 `12_1`——**永不相等，Remove 静默失败**，链原样返回。你的订阅照样叠着，泄漏原封不动。**"为什么匿名 lambda 连 -= 都做不到"的完整答案就是这一段**——不是语法限制，是相等性判定 + 每个位点独立生成方法。

### 你的语法问题：`onClickEnter -= RaiseTrigger(InteractionTrigger.Selected);`

**带括号 = 调用（现在立刻执行），不带括号 = 引用（方法本身当值用）**：

```csharp
onClickEnter -= RaiseTrigger(Selected);   // 编译错误：这是"调用"，void 不能当 -= 的参数
onClickEnter -= RaiseTrigger;             // 语法对，但签名不合（见下）
```

第二行为什么也不行：`onClickEnter`（Interactable 基类的事件，无参或别的签名）和 `RaiseTrigger(InteractionTrigger, ObjectTagSO)`（两参方法）**签名不匹配**——原代码用 lambda 就是在做**签名适配**。适配器必须存在，问题只在于它是匿名的（不稳定）还是命名的（稳定）。

### 正确修法（讲义第四节方案 A 的落地，直接可抄但你要写进自己的文件）

```csharp
private void OnEnable()
{
    onClickEnter += HandleClickEnter;      // 命名适配器
    onHoverEnter += HandleHoverEnter;
    onHoverExit  += HandleHoverExit;
}
private void OnDisable()
{
    onClickEnter -= HandleClickEnter;      // 同一个命名方法 → (Target, Method) 相等 → 减得掉
    onHoverEnter -= HandleHoverEnter;
    onHoverExit  -= HandleHoverExit;
}
private void HandleClickEnter() => RaiseTrigger(InteractionTrigger.Selected);
private void HandleHoverEnter() => RaiseTrigger(InteractionTrigger.HoverEnter);
private void HandleHoverExit()  => RaiseTrigger(InteractionTrigger.HoverExit);
private void OnDestroy()        => RaiseTrigger(InteractionTrigger.ObjectDestroy);
```

### 另外：OnDestroy 不能注释掉了事

你把 `RaiseTrigger(ObjectStart)` 直接注释了——那订阅者的"销毁通知"就永远收不到了。正确做法是把参数改成 `ObjectDestroy`（枚举 57 行定义着）。**删功能 ≠ 修 bug**。
