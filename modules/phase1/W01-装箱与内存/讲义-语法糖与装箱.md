# W01 补充讲解：语法糖、Format/Concat 与装箱的真正判定法

> 起因：训练者问"Format、Concat 是什么听不懂"。这暴露了一个关键缺口：不知道 `+` 拼接和 `$""` 插值是语法糖——它们在编译时被翻译成方法调用，而装箱就藏在翻译后方法的**参数类型**里。

## 一、核心概念：语法糖（Syntax Sugar）

C# 里很多写法不是"语言天生就会"，而是编译器在你看见不到的地方把它**翻译成别的东西**。`+` 拼接和 `$""` 插值就是两块最典型的糖。

## 二、第一层：`+` 号是假的

你写的：
```csharp
string s = "Score: " + score;
```

编译器实际生成的（近似）：
```csharp
string s = string.Concat("Score: ", score.ToString());
```

- `Concat` 是 `System.String` 类自带的静态方法，作用：把几个 string 连成一个新的返回。
- 它的签名：`public static string Concat(string str0, string str1)` —— **参数是 string**。
- score 是 int 不是 string，编译器就在传参前先帮你调 `score.ToString()` 换成 string。
- 全程没有 object 出现 → **没有装箱**，只有字符串分配。

## 三、第二层：`$` 插值也是假的

你写的：
```csharp
string s = $"Score: {score}";
```

编译器实际生成的（近似，Unity 的 C# 9）：
```csharp
string s = string.Format("Score: {0}", score);
```

- `Format` 也是 `System.String` 的静态方法，作用：拿到模板 `"{0}"` 和参数，把参数填进坑里返回结果。
- 关键签名：`public static string Format(string format, object arg0)` —— **参数是 object**！
- score 是 int（值类型），要塞进 object 参数就必须**先装箱**：堆上造盒子 → 复制值进去 → 传盒子的引用。
- 所以 `$"{score}"` = 装箱一次 + Format 内部 ToString 的字符串 + 结果字符串。

## 四、判定法（本课唯一要记住的东西）

**装箱不藏在语法外表里，藏在翻译后方法的参数类型里：**

| 你写的 | 翻译成 | 参数类型 | 装箱？ |
|--------|--------|---------|--------|
| `"x" + i` | `Concat("x", i.ToString())` | string | ✗ |
| `$"{i}"` | `Format("{0}", i)` | **object** | ✓ |
| `object o = i` | box 指令 | — | ✓（标准装箱） |
| `i.ToString()` | 直接在值上调用 | — | ✗ |

背"哪个语法会装箱"是脆的（C# 10 换了 handler 就翻车）；**看签名**是稳的，任何时代都能自己推出答案。

## 五、类比

- **Concat 是"只收纸的胶水"**：你手里是零件（int），它让你先抄一张零件说明纸（ToString），粘的是纸——零件本身没进堆场。
- **Format 是"什么都收但必须打包的快递"**：不管你是什么，先塞进统一快递箱（object 盒子），箱子进堆场——零件连箱一起寄，这就是装箱。

## 六、怎么自己验证（三条路，不信教练）

2. B5 实验：循环里分别测 `$"{i}"` 与 `"x" + i` 的每次迭代分配量，差值 ≈ 24B——那就是盒子的重量。

## 七、追问：为什么 ToString 不装箱，参数却装箱？（2026-10-26 补）

**疑问**：`Debug.Log(i)` 装箱、`Debug.Log("x" + i)` 不装箱——可后者里 i 也 ToString 了，矛盾吗？

**不矛盾，因为因果是反的**：不是"ToString 需要先装箱"，恰恰是——**在值类型上直接调用 ToString 根本不需要 object**。编译器知道 i 是 int（静态类型已知），生成的指令是"走到那个值上直接调用方法"，全程不需要引用、不需要指针。

**装箱的真正触发点：参数槽位需要"引用"，而裸的值类型给不出引用。**

- 引用（指针）只能指向堆上带对象头的对象；int 是 4 字节裸值（在栈/寄存器里，没有对象头），**指针指不了它**。
- `Debug.Log(object)` 的参数槽只收引用 → 运行时必须在调用边界造一个堆上盒子，把值复制进去，传盒子的引用 → **装箱发生在 Debug.Log 还没开始执行的时候**（IL：`box` 在 `call` 之前）。
- 进入方法体后，ToString 是在**已经装好的盒子**上调的。

时序对比：

```text
Debug.Log(i):
  ① box int（参数槽要引用，裸值给不出）  ② call Log(object)  ③ 方法内在盒子上 ToString

Debug.Log("x" + i):
  ① 直接在裸值上调 i.ToString()（编译器知道类型，不需要引用）→ 产出 string
  ② Concat(string, string) → 产出 string
  ③ string 本身就是引用，传给 object 参数只传指针，不装箱
```

**一句话规则（本节的收获）**：装箱发生在"**需要一个指向值类型的引用**"的时刻——object 参数、接口变量、非泛型集合元素（`IComparable c = i`、`IEnumerable<T>` 遍历 `List<T>` 装箱 enumerator 也是同一原理）。凡编译器能静态确定类型直接调用的地方，都不装箱。
