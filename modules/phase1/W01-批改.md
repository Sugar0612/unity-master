## 任务 A 逐题批改

### A1（1/3）栈与堆
- **硬伤：概念混淆**。"栈队列是先进先出"把**数据结构**（栈=LIFO、队列=FIFO）和**内存区域**（调用栈 vs 托管堆）混为一谈。本题问的是后者。
- 正解：**调用栈**存方法帧和局部变量（值类型的值本身、引用类型变量的"地址"）；**堆**存对象实例、数组、装箱值、被闭包捕获的变量。
- 值类型在堆上的场景：你的例 a（**类字段 ✓ 完全正确**）、装箱、被闭包捕获、迭代器/async 状态机的局部变量（会被提升为堆上字段）。
- 例 b 的判定（**2026-10-26 教练修正**：原批"不是装箱"判重了，精确版如下）：`$"{a}"` 在 Unity（C# 9/Roslyn）下编译为 `string.Format("{0}", a)`，而 Format 的参数是 `object`——**装箱确实发生**（把 a 装进盒子传参），训练者的结论碰巧成立。但**理由是错的**：装箱不发生在"转化为 string"的时刻，而是发生在"值类型传给 object 参数"的时刻；ToString 产生的 string 本身永远不是装箱。若在 .NET 6+/C# 10+ 下，$ 插值走泛型 handler，不装箱——这是编译器版本相关的。详见对话讲解与 B5 实验。

### A2（0.5/3）数组的内存布局
- **核心错误：数组永远在堆上**。`new int[10]` 是引用类型分配（对象头 + length + 10 个 int 连续内联），和 int 是不是值类型无关。
- 第 2 问方向对但表述不准：arr 变量本身在**栈**上，存的是**堆上数组对象的引用**——说"元素的地址"不对，引用指向的是数组对象起始处（前 16 字节是对象头和长度，元素在其后）。
- 第 3 问"存在内存中"是无效答案：10 个 int **内联存在堆上数组对象里，未装箱**——这正是 `int[]`/`List<int>` 高效的原因，也是 B2 实验要让你亲眼看到的东西。

### A4（0，诚实空白）
- 补讲：64 位运行时下，装箱一个 int 占 **24 字节**（对象头 8 + 方法表指针 8 + 数据 4，对齐到 24）。
- 推算：100 万个装箱 int ≈ 24MB 的盒子本体 + `List<object>` 的引用数组 8MB ≈ **32MB**；`List<int>` 只要 ≈4MB。差 8 倍，且每个盒子都是 GC 要扫描回收的对象——GC 压力的差距比内存差距更大。

### A5（0.5/3）struct 复制
- 你两个例子都**不是"复制"问题**：①"被 class 包含"是**布局**问题（在堆上≠被复制）②"List<struct> 反复 new/destroy"——List<T> 对值类型元素是内联存储，没有装箱也没有逐元素销毁。
- 真正的隐式复制场景：
  1. **大 struct 按值传参**——每次调用整份拷贝
  2. **读 struct 属性**——每次访问都复制一份（Unity 经典：`transform.position` 每次 getter 拷一个 Vector3；大 struct 属性放循环条件里反复读就是反复拷）
  3. **非 readonly struct 字段上调用方法**——编译器防御性拷贝，每次调用先拷一份
