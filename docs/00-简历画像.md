## 三、面试风险 Top 5（训练期间优先消除）

4. **代码规范声明 vs 仓库实况**：GitHub 公开仓库若被看，拼写/死代码直接打脸。W11 大扫除 + 今后新代码保持

## 四、同步更新机制

- **每个门禁（M1~M4）通过时**：更新上表"训练后"列，✗/△ 项逐步转 ✓
- **W12（M2）后**：SNNU 真机 WebGL 出包 + RSHE 性能审计报告 → 简历"渲染优化/性能优化"条目可升级为带数据版本（"通过 Profiler 定位 XX，帧时间从 X 降到 Y"——比"稳定60帧"有说服力）
- **M4 毕业后**：生成新版简历素材——毕业项目 + 8 个手写 shader + 框架硬化 + 重构案例，全部有仓库可验证
- **原则**：简历上每一句话，都要能在面试现场顶住三层追问——达不到的条目先撤下，训练补上再写回

## 五、坦白记录（2026-10-13）

训练者主动坦白：简历中的优化内容（LOD、遮挡剔除、合批、真机 60FPS 相关表述）基本未亲自实操过，Profiler 从未使用，相关策略为背诵的八股文。

**对评估的影响**：
- C 维度（性能优化）实操定级由 2.0 下调至 **1.5**（笔试理论复述 50% 是背诵结果，不能作为实操证据）
- 对照表"渲染优化"条目 △ → ✗；面试风险 #1 升级为最高风险
- 其余定级不受影响（架构、交付、网络代码均有真实代码证据支撑）

**为什么这次坦白价值很大**：
1. 它解释了笔试 C 部分的"半对半错"模式——不是学过忘了，是背过没做过。训练起点因此更准：W7-W9 按零实操设计，不跳步
2. 它把训练目标从"会答题"校准为"把简历变成真的"：M2（性能审计 + 真机出包）通过后，这些条目以带数据的真实版本写回简历
3. 主动暴露自己的不诚实点，是工程师最重要的品质——训练场的"虚假自信记录"机制因此保持零记录

**背诵的定位**：八股文不是罪，是理论框架的起点。缺的是"手在里面"——知道合批这个词和亲手在 Frame Debugger 里看到合批被打断、查原因、修复，是两种能力。W7 开始补的就是后者。
