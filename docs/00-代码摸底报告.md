## 二、SNNU 增补发现（最新项目，2026-06~08）

### 关键发现：自研框架包

SNNU 通过 `Packages/manifest.json` 引用两个本地 UPM 包：**`com.sug.essentials`**（DI 内核：`[Service]`/`[Inject]` 特性、反射扫描注册、Global/Scene 双生命周期容器、编辑器 `sceneSaving` 钩子自动挂载 Bootstrap）和 **`com.sug.essentialsservices`**（场景/文件/UI/事件总线服务，含 WebGL IO 抽象）。这是初中级工程师不会产出的可迁移抽象。

### 明确的成长证据（对照旧毛病逐项核验）

| 旧毛病 | SNNU 状态 |
|--------|----------|
| FindObjectOfType 滥用 | **已修**——Game 内 0 处，框架用 `FindObjectsByType` 且带 `#if UNITY_6000_0_OR_NEWER` 版本门控 |
| 每帧 new List | **已修**——Update 内无集合分配 |
| Camera.main 不缓存 | 未复发（纯 UI 项目） |
| 复制粘贴转发链 | **部分修**——事件化为主，仍有少量转发残留 |
| 死代码不删 | **未修**——空生命周期方法、整段注释块、死 Looper 依旧 |
| 拼写错误成片 | **未修**——"Practice" 三种拼法（Parctice/Partice/parcitc）、"Initialization" 三种拼法并存 |
| （新暴露）资源生命周期 | **新弱项**——见下 |

### shader/VFX 集成（AI 写 shader，他写胶水）

- **好样板** `UIRippleEffect.cs`：`static readonly int` PropertyToID 缓存 ×7、`Instantiate(_image.material)` 运行时材质实例化、`SetMaterialDirty()`、`[Flags]` 触发器位掩码——AI 的 shader 被工程化方式接进了主面板
- **差对照** `ImageEdgeFlowEffect.cs`：每帧字符串 `GetFloat/SetFloat`（未 PropertyToID）、`new Material()` 实例从不 Destroy——同一作者两种水准并存
- VFX Graph 集成为零：`.vfx` 资产存在，但 C# 侧无任何 `VisualEffect` API 调用

### 仍然存在的硬伤

1. **WebGL 是纸面目标**：运行时代码 4 处 `using UnityEditor...`（`TheoryPanel.cs:8` 等）会让玩家端构建直接编译失败——证明从未出过包；`AssManager` 异步读题与 `TheoryPanel.Start` 同帧取题在 WebGL 上必崩（平台差异只处理了 IO 层、没处理时序层）
2. **生命周期不闭环**：UI 选项只 `SetActive(false)` 不销毁（Destroy 被注释）、材质实例泄漏、`ControlBase.OnEnable` 匿名 lambda 重复订阅无退订、`OnDestroy` 发错触发器（发的是 ObjectStart）、`while (!IsValid() && !IsDone)` 逻辑写反的死守卫
3. **改上游不管下游**：8 月框架拆分重构后，SNNU 工作区 55 个变更未提交、manifest 指向新包，当前大概率编译不过
4. `TheoryPanel.cs` 620 行 God Class 混 7 种职责；`UIGlowEffect.cs` 类名与文件名不一致（组件无法挂载，重命名后未验证）

## 三、跨项目共性问题（训练要打的靶子）

### 1. "会用但不懂原理"——运行时语义理解不到位（最核心问题）

- **static [SyncVar]**（CNCore `MyVRStaticVariables.cs:11`）：不理解 Mirror Weaver 只织入 NetworkBehaviour 实例字段
- **网络竞态**（RSHE `Transporter.cs:70-83`）：onClick 里发 [Command] 后同步读 SyncVar，必然读到旧值
- **属性 setter 自引用递归**（CNCore `LocalAudioBase.cs:8-12`）：C# 属性语义基础漏洞，且从未被运行验证
- **异步时序竞态**（SNNU `AssManager` vs `TheoryPanel.Start`）：异步初始化未完成就被消费——与网络竞态同根：**对"异步操作何时真正完成"缺少心智模型**
- 其他：MonoBehaviour 被 new（CNCore）、反射代替泛型约束（RSHE）、位运算 & 代替 &&（RSHE）、赋值当比较（RSHE `WarningLinker.cs:54`）、生命周期误用（移动写进 LateUpdate、僵尸同步链）

### 2. 复制粘贴代替抽象（旧项目严重，SNNU 已缓解）

RSHE 任务分发链约 1,500 行有效信息不到 200 行；CNCore 双套激活类 + 整套旧版并存；AIStarLink 懒加载样板复制 5+ 处。

### 3. 性能意识（旧项目严重，SNNU 部分缓解）

- RSHE `MyVRPlayerRig.FixedUpdate` 每物理帧 3 次 `GameObject.Find`
- AIStarLink `UIToolkit` 每帧 new PointerEventData + new List（两个调用点）
- FindObjectsOfType 家族：RSHE 54 处、CNCore 24 处、AIStarLink 15 处、SNNU 0 处（已修）
- SNNU 残留：每帧字符串属性查找、`text += c` 逐字拼接

### 4. 工程卫生差（五个项目贯穿，未随成长改善）

- 死代码：CNCore 683 行、RSHE ~1,000 行、SNNU 空方法 + 注释块依旧
- 拼写错误系统化：跨项目 40+ 处，同一单词多种拼法
- **⚠️ 安全事故级**（AIStarLink）：明文 API Key 序列化进场景并推 GitHub；Start 里打印密钥
- 可交付性：AIStarLink 与 SNNU 运行时代码均有 `using UnityEditor`（出包必失败）——**两个声明了发布目标的项目从未验证过构建**

### 5. "导入/复制了但没消化"模式

AIStarLink 的 SuperScrollView 死依赖、抄 Source SDK 的 ASMath（原注释都没删）；SNNU 的 VFX 资产导入但零代码集成。

## 四、真实亮点（训练中要保住和放大的）

1. **自研框架能力**（SNNU 阶段）：DI 内核 + 服务层 UPM 包跨项目复用、编辑器自动引导、反射扫描注册——抽象能力进入中高级区间
2. **数据驱动直觉**：RSHE `GameTaskItem` 的 `UnityEvent` Inspector 编排、CNCore 的 SO 剧本驱动
3. **API 演进意识**：Unity 6 新旧 API 双路径门控、WebGL/桌面 IO 统一抽象
4. **shader 集成工程化**（`UIRippleEffect` 的 PropertyToID + 材质实例化 + 位掩码触发）——虽然 shader 本身依赖 AI
5. 协程熟练正确、Addressables 场景管线基本正确（AssetReference 强类型、句柄 Unload）、git 提交信息规范
